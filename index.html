agent-sow-v1 // a contract shape for recurring agent work

Agents do recurring work. Firewalls only know strangers.

An Agent SoW is a signed statement of work between two parties whose software agents work together: scope, inputs, deliverables, price, volume, term. The defining rule is honesty about enforcement. Every clause is graded by what a machine can actually do about it.

The machine margin. A clause that claims more enforcement than the runtime delivers is not conformant.

The enforcement gradient

Every "smart contract for AI agents" pitch fails the same way: it pretends everything is enforceable. An Agent SoW carries exactly one grade on every clause, and renderers must show it. Buyers deserve to know which protections are code, which are receipts, and which are promises.

Enforced

Violations are refused

The runtime refuses out-of-scope requests, over-limit traffic, and malformed deliverables mechanically, with a typed refusal, before the work runs. A grade a deployment must earn, not claim.

Evidence

Records are signed

Signed task history, tamper-evident audit chains, settlement receipts held by both sides. A dispute is read from records, not reconstructed from memory.

Recorded

Promises are named

No training on client data. No sharing with third parties. No machine can verify these. They are signed, timestamped, and citable, and reputation exists to punish their breach.

Eleven clauses, one document

The clause list is the familiar consulting SoW, made precise enough for runtimes to act on. Owners sign; agents work; each party's own node enforces from its own countersigned copy. There is no central contract store to trust or to lose.

The asymmetry, named

Clauses that protect the provider run at the provider's own gate. Trustworthy: a node guarding its own interests enforces honestly. Clauses that protect the client are checked by software the provider runs, and a provider checking its own homework is trust wearing an enforcement costume.

So the spec refuses to launder it. The client's node independently verifies deliverable form on receipt. And refund-on-failed-task may only be graded enforced where a neutral clearing function will execute the reversal on signed evidence, without the provider's cooperation. Where no such clearing exists, the clause is graded evidence, and shown that way. That is the honest state of most deployments today, and section 8 of the spec is written so nobody can pretend otherwise.

A shape you graduate into

Casual traffic never requires paperwork. Two agents saying hello are governed by ordinary admission policy: identity checks, stranger limits, hold queues. The SoW is for the moment a relationship turns into commitments, money, standing access to data, promised deliverables. Then the scattered controls consolidate into one document both owners signed, and the interesting constraints become per-relationship instead of per-packet.
